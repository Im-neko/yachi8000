# 自作 VRM を作って `web/` に載せた記録

キャラクター設定画から VRM を作り、`agent/data/avatar.vrm` に置いて `web/` で動かすまでにやったことと、
**web 側が VRM に求めるもの**の整理。VRM そのものは**リポジトリに入れない**（→ `avatar.md`、F-62、D-36 の 3）。

制作はこのリポジトリの外（ローカル専用の git。公開しない）で行った。ここに書くのは、
モデルを差し替えるとき・別のモデルを作るときに効く事実だけ。

## 1. 何をしたか

| 段階 | 内容 | 状態 |
|---|---|---|
| 生成と組み立て | 設定画 → 3D（Charakuru kit 1.0.3 の手順）。体・頭・髪・スカートを別メッシュに分け、ボーンと揺れ骨を設定 | 完了 |
| 表情 | 口（`aa / ih / ou / ee / oh`）・まばたき・感情を**本物のシェイプキー**で作る。視線は目のボーンの回転 | 完了 |
| 顔まわりの絵の直し | 目の周りの「くま」（テクスチャに描かれた濃いピンクの輪）、眉・下まぶたの絵を肌色で塗り直す | 完了 |
| 当たり判定 | 髪が体・肩・腕・手へ突き抜けるのを、コライダーの作り直しで抑える | 完了 |
| 待機姿勢 | 手のひらが上着にめり込むのを、腕の角度で直す（→ `web/src/pose.ts`） | 完了 |
| `web/` での確認 | ブラウザで表示・待機・表情・口形を確認 | **一部のみ**（§4） |

## 2. web 側が VRM に求めるもの

モデルを作る・選ぶときの条件。**満たしていないと、モデルを差し替えた瞬間に一部だけ黙って効かなくなる。**

- **VRM 1.0 で書き出す。** 表情はプリセット名（`neutral / happy / angry / sad / relaxed / surprised`、口形 `aa / ih / ou / ee / oh`、`blink`）でしか呼ばない（→ D-36 の 1）
- **口形のシェイプキーは、母音の重みの合計が 1 付近に収まる前提で作る。** リップシンクは複数の母音を混ぜる。合計が 1 を大きく超えると顎の下が破綻する
- **視線は `lookAt.type = bone`**（目のボーンの回転）。目のボーンは**眼球の中心**（虹彩の約 17.5 mm 奥）へ置き、虹彩とその上のハイライトだけを骨に乗せる。回す量は範囲写像の `output_scale`（左右 11° / 上 6° / 下 8° ＝ 虹彩の移動 3.5 / 2.0 / 2.5 mm）。このモデルは虹彩が大きく（25 mm、目の穴は 38 mm）動ける幅が小さいので、大きくすると穴の外へはみ出す。web は `vrm.lookAt.target = camera` を設定する（`web/src/stage.ts`）。**ボーンが虹彩から遠いと（既定では約 48 mm 奥だった）、少し回しただけで虹彩が大きく動く**
- **揺れ骨のコライダーは VRM に入れて書き出す。** three-vrm が `VRMC_springBone` を自動で読み、髪が体を抜けない。`web/` 側にコードは要らない
- **待機姿勢は `web/src/pose.ts` が決める。** 上腕の下ろし角（`ARM_REST`）は**モデルの寸法で決まる**ので、別のモデルでは測り直す（下記）

### 腕の角度はモデル固有

`pose.ts` の上腕の角度は、このモデルの上着の裾（体の中心から ±0.19 m）に手がぶつからない値として実測した。

| 上腕を下ろす角 | 手の頂点が体の中に入る割合 |
|---|---|
| 1.25 rad（以前） | 約 6 割（最深 51 mm） |
| 1.15 rad | 約 2 割 |
| **1.05 rad（現在）** | **0** |

**副作用:** 腕が体から約 7 cm 離れて見える。以前の（別キャラの）モデルでは 1.25 が合っていた。
**モデルごとの設定値にはまだしていない**（`pose.ts` の定数のまま）。別のモデルを常用するなら、設定ファイルへ出す
（`avatar` 節に足す。互換は意識しなくてよい → 未リリース）。

## 3. 作って分かったこと（モデルを作り直すとき用）

- **書き出し時に VRM アドオンが腕を T ポーズに直す。** コライダーは骨の子なので、位置は**休め姿勢ではなく T ポーズの骨**を基準に決めること（休め姿勢の座標だと約 4 cm 浮き、向きも約 37° ずれた）
- **手のコライダーをスカートの群に入れてはいけない。** 待機で手がスカートを太ももへ押し込み、突き抜けが 18 mm → 43 mm に悪化した。髪の群にだけ入れる
- **シェイプキーの付いたメッシュは、キットの組み立て工程が弾く。** キーは最後に足す。作り方はスクリプトにして、元の blend から再生成できるようにしておく
- **目の周りの暗い斑はテクスチャの絵が原因だった。** 影（MToon の陰）や法線ではない。切り分けにはプレビューで画面の点から UV・面を引くと速い
- **UV 上の距離をピクセル定数で扱うと、島ごとの縮尺の違いで片目だけ直らない。** 距離ではなく「皮膚の三角形の上の色」で拾う
- **確認用の静的サーバは `Cache-Control: no-store` を返すものにする。** 古い VRM を使い回されて、直ったのに直っていないように見えたことが 2 回あった
- **`requestAnimationFrame` はブラウザが非表示の間は止まる。** 物理の計測は自前で 1/60 秒刻みに進める

### 当たり判定の結果（髪が体の中に入る頂点数。待機姿勢で頭・首・体を動かした平均）

| | 前 | 後 |

## 4. `web/` で確認したこと・していないこと

スタブの API（`/api/v1/avatar/config`・`/model`・`/events`）と dev サーバで、ブラウザのペインから見た。**実機（クラスタ）では未確認。**

確認した:

- VRM が表示され、待機の立ち姿になる（コンソールエラーなし）
- `expression: happy` で目が閉じる
- 口形 `aa` と `ou` で口が開く
- 手のひらが上着にめり込まない（待機）

**確認していない:**

- 口形 `ee / ih / oh`（送っただけで、画像では見ていない）
- まばたきの自動動作、web でカメラへ目が追従する様子（視線の回転はプレビューで骨を回して確認した）、`sad / angry / relaxed / surprised`
- 身振り（素材の VRMA が無い → Q-27）
- 実機でのモデル配信（`/data/avatar.vrm` の置き換え、`settings.yaml` の `avatar` 節）
- 斜めからの見え方（口・目は正面〜やや斜めまでしか見ていない）

## 5. 既知の弱点（正直に）

- 前髪・側面の髪の約 380 頂点は、顔の肌に密着する作りで、「体の中に入る」計測に常に引っかかる（設計上の値）
- スカートの約 5 % が計測上「入っている」。大半は上着の裾の内側で見えない
- 待機の揺れ（呼吸・体重移動）で、右手の 14 頂点が最大 14.6 mm 上着に入る
- 口角の三角形が最大 10 mm（辺の 2 倍）伸びる
- **驚き（`surprised`）で目が見開かない**（眉だけ上がる。上まぶたを上げる形が足りない）
- 鼻の両脇の陰がまだ少しギザつく
- 閉じ目の両端が少し丸く鈍い
- 板方式（透明度の差し替え）とシェイプキー方式は別物。**シェイプキー方式を採った**ので、`blink=0.5` は半目になる（板方式だと開いた目と閉じ目が重なって見える）
