# 01. 概要・スコープ

## 目的

3D キャラクターの姿を持つパーソナル AI アシスタントを作る。テキストのボットではなく、**姿と声を持ち、日常の中に居る**ことを目指す。

## 利用シーン

1. **音声で相談する** — Discord のボイスチャンネルに入ると常駐しているアシスタントが応答する。手が塞がっているとき、考えを整理したいときに使う
2. **姿を見ながら話す** — ブラウザでアバターのページを開くと、話者に合わせて表情・口・視線が動く。ビデオ通話に相当する体験をここで得る
3. **チャットで頼む** — Discord / Slack のテキストから「明日 10 時に○○」「これ調べておいて」を投げる
4. **自分好みに仕立てる** — 名前・人格・口調・3D モデル・声を、設定ファイルや画面から変えられる。人格が勝手に変わってほしくないときは固定モードにする
5. **外の出来事を知らせてもらう** — 通話中に外部システムから通知が届くと、会話に割り込んで「○○ からのメッセージです。〜」と読み上げる。手を止めて画面を見に行かなくてよくなる
6. **思い出してもらう** — 過去に話した好み・約束・人物関係を踏まえた応答が返る

## 想定利用者

**単一利用者（オーナー個人）。** 一般公開・マルチユーザー提供は想定しない。ただしテナント分離の構造（Discord ギルド / チャンネル単位）は 先行実装と同様に持たせ、将来の家族・友人利用を塞がない。

## スコープ

含む:

- Discord VC での音声対話（聞く・話す）
- ブラウザ上での VRM アバター表示と、発話への反応
- Discord / Slack のテキストチャット応答
- 外部システムからの通知を受ける HTTP API と、VC への割り込み読み上げ
- リマインダー・簡単な日常タスクの受付と実行
- 長期記憶（知識・人物・好み）の蓄積と参照
- スキルの自動生成と、承認を経た有効化
- **名前・人格・口調・3D モデル・声のカスタマイズ**（設定ファイルと UI の両方から）
- 人格・口調を変化させない固定モード

含まない（非スコープ）:

- **Discord / Slack への映像送信**（技術的に不可。→ C-01, C-02）
- 一般公開・課金・マルチテナントの運用機能
- スマートフォンアプリ、ネイティブデスクトップアプリ
- 音楽再生・ゲーム等の娯楽 Bot 機能
- 自律的な外部システム操作（決済・送信等の不可逆操作）。→ 不可逆操作は必ず人間の確認を挟む

## フェーズ分割

各フェーズは**単体で使える状態**になることを条件とする。「基盤だけ作って動かない」フェーズは置かない。

| 順 | フェーズ | 完了条件 | 主な要件 |
|---|---|---|---|
| 1 | **Discord テキスト対話** | **Discord** のテキストで会話でき、記憶が残る。**設定ファイルで名前・人格を変えられる** | F-01, F-02, F-04, F-30, F-32, F-60 |
| 2 | **Discord 音声出力** | 呼びかけるとテキストで受け、**Discord VC** で声が返る | F-11, F-12 |
| 3 | **外部通知** | 外部から POST した通知が、通話中の **Discord VC** に割り込んで読み上げられる | F-15〜F-19 |
| 4 | **スキル自己改善** | 会話からスキルが自動生成され、**Discord から承認**すると効く。**人格の変化が記録され、戻せる** | F-40〜F-43, F-33, F-34 |
| 5 | **Slack 連携** | Slack のテキストから同じことができる。**Discord 側が一通り揃ってから着手する** | F-03 |
| 6 | **アバター** | ブラウザで VRM が発話に同期して動く。**設定 UI から人格・モデル・声を変えられる** | F-20, F-21, F-22, F-61, F-62 |
| 7 | **音声入力** | VC で話しかけると音声で応答が返る（A → B → C は D-19） | F-13, F-14 |

**2026-09-11 にオーナー判断で更新**: スキル自己改善をアバターより前に出し、**アバターと音声入力を最後尾に置いた**。

理由の整理:

- **スキル自己改善は「使うほど賢くなる」という中核価値**であり、テキストと音声が揃った時点で単独で効く。アバターを待つ必要がない
- **アバターは体験の質を上げるが、機能としては他のどれにも依存されていない。** 後ろに置いても他が止まらない
- **音声入力は最後**。残る不確実性（発話区間の切り出し、Q-03）がここに集中しており、かつ B（Web のマイク入力）という代替路が用意されている（D-19）
- **Discord 連携は Slack より先**。フェーズ 1〜4 はすべて Discord 上で完結し、Slack は Discord 側が一通り揃ってから着手する。**Discord が主、Slack は従**という位置づけを崩さない

この配置により、フェーズ 1〜5 は「**依頼はテキスト、返答は音声、会話するほどスキルが増える**」という形で完結する。**片方向（アシスタントが話す）だけでも実用になる**ことが前提で、これは外部通知（フェーズ 3）が単独で価値を持つことと同じ理由。

**⚠ アバターが後ろに下がったことの副作用**: 設定 UI（F-61）は `web/` の上に作るため、**フェーズ 6 まで存在しない。** それまでカスタマイズ手段は**設定ファイルの手編集だけ**になる（F-60）。名前・人格・口調・話者 ID・話速はフェーズ 3 時点で設定ファイルだけで変えられることを確認済み。

**進捗（2026-09-11）**: フェーズ 1〜3 実装済み。フェーズ 4 から未着手。

## 成功条件

- **常用されること。** 週に数回以上、実際に頼りにされている状態
- 応答レイテンシが会話を切らさないこと（音声応答で体感 2 秒以内を目標）
- 「前に話したこと」を踏まえた応答が返ること
- 障害時に**黙って劣化しない**こと（→ フォールバック禁止。落ちるべきときは落ちて通知する）
